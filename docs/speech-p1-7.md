## หน้า 1 · ชื่อเรื่อง (~20 วินาที)

สวัสดีครับ/ค่ะ พวกเรากลุ่มรวมกันตายหมู่ วันนี้จะนำเสนอ fslek ซึ่งเป็น filesystem ที่เก็บทุกอย่างไว้ใน RAM และต่อเข้ากับ Linux ผ่าน VFS ใช้งานได้จริงเหมือนโฟลเดอร์ทั่วไป

---

## หน้า 2 · What does it have? (~40 วินาที)

ถ้ามองจากฝั่งผู้ใช้ fslek ก็คือโฟลเดอร์ธรรมดา ใช้คำสั่งปกติได้หมด ทั้ง mount, umount, สร้างไฟล์, อ่าน, เขียน, mkdir, ls

เจ็ดอย่างแรกคือที่โจทย์ให้มา เราทำครบ แล้วทำเพิ่มคือ rm กับ mv รวมถึงจำกัดขนาด ดูสถิติ และวัดความเร็ว ซึ่งจะเล่าในหน้าหลังๆ

จุดที่ต่างจากโฟลเดอร์ปกติคือ ข้อมูลอยู่ใน RAM ไม่ได้อยู่บน disk จึงไม่ต้องรอ disk แต่พอ umount ข้อมูลก็หาย ตัวโปรแกรมเป็น kernel module ที่โหลดเข้า Linux ได้เลย ไม่ต้อง compile kernel ใหม่

---

## หน้า 3 · VFS (~1 นาที)

เวลาเราพิมพ์ cat หรือ echo ตัวโปรแกรมไม่รู้เลยว่าไฟล์อยู่บน disk หรือ RAM เพราะทุกคำสั่งจะผ่าน system call ไปที่ VFS ก่อน

VFS เหมือนเคาน์เตอร์กลางของ Linux รับคำสั่งมาแล้วส่งต่อให้ filesystem ที่ดูแลไฟล์นั้น ถ้าเป็นไฟล์บน disk ก็ส่งให้ ext4 ถ้าเป็น RAM ของ Linux เองก็ส่งให้ tmpfs

งานของเราคือเพิ่มช่องบริการใหม่ชื่อ fslek แล้วบอก VFS ว่าแต่ละคำสั่งให้เรียกฟังก์ชันไหนของเรา เราไม่ได้แก้คำสั่งของ Linux เลยแม้แต่ตัวเดียว

---

## หน้า 4 · 5 Files (~1 นาที)

โค้ดทั้งหมดแบ่งเป็นห้าไฟล์ตามหน้าที่

- **fslek.h** คือ header รวม มีค่าคงที่ เช่น ไฟล์ละไม่เกิน 64 MiB มี struct ของข้อมูลไฟล์กับสถิติ และโค้ดที่ทำให้ build ได้บน Linux 6.8
- **super.c** ลงทะเบียน filesystem กับ VFS ตอน insmod จัดการ mount กับ umount รวมถึง option size= สร้าง inode ตอบคำสั่ง df และคิดโควตาด้วย fslek_charge กับ fslek_uncharge
- **dir.c** ทำ create กับ mkdir เอง ส่วน lookup, ls, rm, rmdir, mv ใช้ของ libfs ที่ Linux มีให้ โครงสร้างโฟลเดอร์ทั้งหมดเก็บอยู่ใน dcache
- **file.c** ทำ read, write และ truncate ข้อมูลแต่ละไฟล์อยู่ใน buffer ก้อนเดียว จองด้วย kvzalloc และขยายหรือลดขนาดเองได้
- **stats.c** เก็บสถิติรวมให้อ่านจาก /proc/fslek มีจำนวนไฟล์ จำนวนโฟลเดอร์ จำนวน bytes และจำนวนครั้งที่ buffer ขยาย ใช้ atomic_long_t แทน lock

## หน้า 5 · Command → ฟังก์ชัน (~1 นาที)

ตารางนี้บอกว่าแต่ละคำสั่งไปเรียกฟังก์ชันไหน อยู่ในไฟล์อะไร ขอยกตัวอย่างบางแถว

- **insmod** เรียก fslek_init แล้ว register_filesystem ทำให้ Linux รู้จัก fslek
- **mount** สร้าง super_block ใหม่ อ่าน option แล้วสร้าง inode ของ root
- **touch** เรียก fslek_create ไป fslek_mknod เพื่อสร้าง inode ใหม่
- **echo ลงไฟล์** เรียก fslek_write_iter ซึ่งต้องผ่าน fslek_reserve กับ fslek_charge เพื่อขอพื้นที่ก่อน
- **cat** เรียก fslek_read_iter
- **ls, mv, rm** ใช้ฟังก์ชันของ libfs โดยตรง ตอน rm พอไม่มีใครใช้ไฟล์แล้ว จะไป fslek_evict_inode เพื่อคืน buffer
- **umount** ไล่ evict ทุกไฟล์ แล้วคืนหน่วยความจำของ mount นั้น
- **rmmod** ยกเลิกการลงทะเบียน และลบ /proc/fslek

สังเกตได้ว่าเราเขียนเองเฉพาะส่วนที่จำเป็น อะไรที่ Linux มีให้แล้วเราก็ใช้ของเดิม

## หน้า 6 · ชื่อกับ Data เก็บคนละที่ (~45 วินาที)

ไฟล์หนึ่งไฟล์แบ่งเป็นสองส่วน

ส่วนแรกคือ**ชื่อ** เช่น a.txt หรือ docs/ อยู่ใน dcache ซึ่งเป็นของ VFS เราต้องสั่ง pin ไว้ เพราะปกติ VFS ทิ้งชื่อได้เมื่อ RAM ตึง ถ้าเป็น ext4 ก็อ่านกลับจาก disk ได้ แต่เราไม่มี disk ทิ้งไปแล้วไฟล์หายจริง

ส่วนที่สองคือ**เนื้อหา** อยู่ใน buffer ที่เราจองเองใน RAM หนึ่งไฟล์หนึ่งก้อน โดยมี inode เป็นตัวเชื่อมระหว่างชื่อกับเนื้อหา

ส่วนที่จองไว้แต่ยังไม่ได้ใช้ เราทำให้เป็นศูนย์เสมอ ข้อมูลเก่าจึงไม่โผล่กลับมาให้อ่านได้

## หน้า 7 · RAM Scaling (~40 วินาที)

เมื่อเขียนจนที่ไม่พอ buffer จะขยายทีละเท่าตัว จาก 4 KiB เป็น 8, 16, 32 KiB ไปเรื่อยๆ

เหมือนย้ายบ้าน ถ้าขยายทีละนิดก็ต้องย้ายบ่อย เราจึงย้ายทีเดียวไปบ้านที่ใหญ่กว่าเดิมสองเท่า

- **ข้อดี** เขียนต่อท้ายบ่อยๆ ได้โดยไม่ต้องย้ายข้อมูลทุกครั้ง
- **ข้อเสีย** มีที่เหลือที่ไม่ได้ใช้ เช่น ไฟล์ 5 MiB จองจริง 8 MiB ซึ่งตรงกับปัญหา contiguous allocation ที่เรียนใน Lecture 12

ต่อไปจะเป็นเรื่องที่หลายคนใช้ไฟล์พร้อมกันครับ/ค่ะ
